# moxie

Moxie is a design language, a language-design exercise: (mostly) compile-time type-safe, immutable, practical functional programming, Go-style channels and fibers, and, in the plain dialect, no garbage collector and no heap. A second dialect, moxie/gc, adds a collector; the two are kept apart because they make different promises. This repository holds the language documents and a reference interpreter written in plain Python 3.

- **Site:** https://slconverse1.github.io/moxie/ (the Site Intro, Tutorial, Mixer’s Guide, Spec, and an in-browser "Try moxie" page)
- **`docs/`** the documents, as the site's source: `index.md` (Site Intro), `tutorial.md`, `spec.md`, `learn/` (the Mixer’s Guide, built from `lessons/`), and `gc/` for moxie/gc, the garbage-collected dialect (its Site Intro, Spec, and Mixer’s Guide)
- **`moxie/`** the reference interpreter (standard library only)
- **`archive/`** the retired Mixer's Guides (`mixers-guide.md`, `mixers-guide-gc.md`), kept for reference and not published; the Mixer’s Guide replaced them. Their code blocks still back `tests/run_guide.py` and `run_gc_guide.py` through frozen corpora.
- **`examples/`**, **`tests/`**, **`INTERPRETER.md`**, **`FIXLIST.md`** the interpreter's samples, tests, notes, and a list of problems found in the Spec and Guide

## Run a program

    git clone https://github.com/slconverse1/moxie
    cd moxie
    python3 -m moxie run examples/gradebook.mxi
    python3 -m moxie test examples/gradebook.mxi

The interpreter needs Python 3.11 or later (tested on 3.11, 3.12, and 3.13) and nothing else. `INTERPRETER.md` lists what it checks and what it doesn't yet.

## Changes

Everywhere the text said "no GC" or "no-GC" for the plain dialect (the Intros, including the Contents entry "Constraints from "GC-free" and "1-pass compiler"", the Specs, the Guide, the reference pages, and the notes and test names) it now says "GC-free". The changelog entries below that describe earlier wording are left as they were.

A parameter declared `Stream[T]` now accepts any collection of `T` as it stands (a `List`, `Array`, `Set`, `Ring`, an `Option`, a `String` for `Stream[Char]`, a `Dict` for `Stream[(K, V)]`), as well as a range or a pipeline, so a call needs no `to_stream()`; a wrong element type is still a type error (`tests/run_streamparam.py`). The rule is in the checker's `compat` (`collection_elem`), the Spec's Streams section, lesson 26 and the Intro.

The Intro now stresses that every collection is a pipeline source as it stands, so a pipeline needs one `collect()` at the end and no conversion in front (a function with a `Stream[T]` parameter takes a collection as it is, too), and the debts list credits C# with this (and the Mixer's Guide has a new lesson 26, "One pipeline, one collect"). Adding it moved later lessons up by one, and the lesson numbers written in the lesson text were updated to match.

The quick view of the history now shows the pages themselves, in full, gliding past as one continuous strip: each page slides into view little by little (the real page, at the place you left it, loaded in a frame, with its title on a card until it appears). Every run moves at one steady speed (`CPX`, 585 pixels a second: 1.5 pages a second on a phone, about 0.7 on a wide iPad), however many pages it covers; one swipe shows up to `MAXRUN` (10) pages, and a larger swipe doesn't go faster, it just carries further. A click, touch or key press stops it and lands on the page nearest to the middle of the screen, which becomes the current page; a held arrow key keeps the strip moving until it is let go. The frames don't touch the history (the history script does nothing inside a frame). Landing moves the history to that entry, as before; it does not add a copy.

Every function in the Spec reference's alphabetical list is now a link to its own page (`docs/ref/NAME.md`, and `docs/gc/ref/NAME.md` for moxie/gc), with the signature, a description with **Parameters** and **Returns**, the effects and permissions, and examples whose output was captured by running them in the interpreter, so a page can't show a result the interpreter doesn't give. The text lives in `tools/refdocs/*.py` and `tools/make_ref_pages.py` builds the pages (and reports any example that fails or differs between the dialects); `tests/run_reference.py` checks that every function has a current page. Mentions of functions in the text link to these pages. Writing them turned up three mismatches, now fixed: decimal `div` leaked a Python exception on a zero divisor and now returns `Err` (code `OUT_OF_RANGE`) as the Spec says (`tests/run_decdiv.py`); the checker's signature for `windows` said `Stream[Array[T]]` but it yields lists; and `min`/`max` of a whole source (`xs |> min()`, giving a `Result`) were missing from the checker's table.

In the Spec reference every function shows its complete signature (`fn name[T Ordered](xs Seq[T]) Stream[T]`, one line per overload, the interface bounds the checker enforces, and `Error` for results) plus an Effect line (prints, parks, uses the system, uses a resource) and a Needs permission line, both read from the interpreter's own tables.

A long swipe, a long trackpad scroll, or a held arrow key now sets the pages flowing by as a strip of cards (section, title and a few words of the text), at a steady two cards a second (`CPS` in `docs/_layouts/default.html`); where the strip stops is the page you land on. Any press, click or key stops it on the selected card.

Navigation by touch or trackpad: a slight swipe moves one frame; a long swipe runs several frames at half a second each (about one frame per 40 pixels of finger travel, up to 12). Any press, click or key stops the run on the frame being shown. A held arrow key still goes one frame per half second.

Holding an arrow key steps through the history at one page per half second. On phones the Contents bar is fixed below the menu bar, a Contents link closes the dropdown and scrolls clear of the bars, and the reference page shows no letter list in the contents area.

A Spec reference of every keyword, type and prelude function with its signature (`reference.html`, generated by `tools/make_reference.py` from the checker's own signature table), and in the intro, Mixer’s Guide and Tutorial each keyword, type, function and a few concept words (package, fiber, channel, tuple, enum, interface, and others) link to it, the first time it appears in a paragraph. The Spec's hard-keyword list now includes `while` and `try_go`, which the parser already reserved.

One history for the text window: swipe left or right on the text, or press the left and right arrow keys (hold to speed through), to step through the intro, guide and spec pages you have visited, up to 50 per site, kept separately for moxie and moxie/gc. The contents area now holds only the moxie / moxie/gc toggle, the menu bar and contents bar are pinned, and on narrow screens the menu bar has arrows to show its ends. In the moxie/gc intro, `[gc]` text is marked by a red line in the right margin. Intro edits: Moxie Superpowers entry in the contents, an Editors paragraph, call by value, reference, name, and need.

A site-wide History: a moxie / moxie/gc toggle, then three trails (Intro, Mixer’s Guide, Spec) each with its own back and forward arrows, kept separately for each site. Spec now follows the Mixer’s Guide in the menu bar, and Tutorial sits with Style outside History. Guide titles read "Moxie Mixer’s Guide".

A name bound with `=` may start with a capital letter and is an ordinary value (`MAXN = 5`, then `println(MAXN)`); only a declared enum case reads as a pattern. Before, a capitalized binding worked only in sizes.

Spec audit (every "is an error" claim in the Spec was probed against the checker): now enforced or fixed are a bare `_` mixed with `_2` in one function, a text slice that cuts a multi-byte character (aborts, and is a compile error for a constant cut), a field called as a function on a constructed value (`P(x: 1).x(2)`), a `forward fn` whose definition has a different number of type parameters, and `regex.must` on a bad pattern (it returned an `Err` instead of stopping). `x = 5 if c` and `x = 1 if c else 2` give messages that point to `if c then a else b`. `tests/run_specrules.py`.

Pages with an outline get a floating "↑ Top" link once you scroll; the monoids lesson no longer carries a GC-free-only remark in the gc guide. `par_map`, `par_traverse`, and `par_map_all` now check `limit:` (a constant of 1 or more) when called after a pipe too, as the Spec says.

The Spec's dated design notes now live on their own pages (`docs/design-notes.md`, `docs/gc/design-notes.md`), linked from the end of the Spec, so the Spec holds only the language as it is.

`NonEmpty` now works as the Spec says: the prelude functions `len`, `min`, `max`, and `map` use a tuple or enum type's own method of the same name, and a piped call inside a method is no longer taken for the method itself. Atoms print as `Atom(10)` and timers as `Timer()`.

Reading aids: both Specs have numbered headings with anchors (`#s9c`) and a sidebar outline, the Mixer’s Guide has a lesson sidebar, each lesson ends with an "In the Spec" line and each Spec section starts with an "In the Mixer’s Guide" line (from `lessons/_spec.txt`; `tools/link_spec.py`, `tests/run_links.py`). The Spec now also covers `lower`, `upper`, `replace_text`, and `unwrap`.

`requires` and `ensures` are gone: a condition goes in the signature as `where`, after a parameter for a precondition and after the result type for a postcondition (`fn withdraw(a Account, amt Int where amt > 0) Account where result.balance == a.balance - amt`). Writing a `requires` or `ensures` line is a syntax error that says to write `where`. `invariant` stays for conditions between fields. An interface member carries its conditions the same way, `fn pick(self, n Int where n >= 0) Int`, and impls are held to them as before. The run-time messages now say "precondition failed" and "postcondition failed". Lesson 55, the Spec (9c), the intros and `moxie doc` follow. Also: the Spec's rule for blocks of children now says a condition loop is refused while `for x in xs` is allowed, and the dead `with` rule left the grammar.

`x++` and `x--` are gone: write `x += 1` and `x -= 1`, the form that also covers `-=`, `*=` and the rest. The statements are a syntax error that says so, and the `incr` rule left the grammar. The Dict and list `get` stays: for a list or an array it is the checked read (`get(xs, 7)` is an `Err` where `xs(7)` aborts), and for a Dict it matches `d(k)`.

`for` is the only loop. `for i < n` and `for read_line() is Ok(line)` loop on a condition, as in Go, and `for true` loops until a `break`; `for x in xs` is unchanged, and a membership test as a condition is written in brackets, `for (n in allowed)` (a header with an `in` at its top level is the iteration form). `while` is now a syntax error that says to write `for`, and the Spec, lessons, std library, tests and editor syntax files use `for`. A `for n in xs` where an `n` already exists gets a note, since it binds a new `n` and does not test the old one. Loop rules (rebinding passes forward, `else`, `break(value)`, labels) are unchanged.

Results and fields are proved at compile time. A linear postcondition (`where` after the result type) is proved at every exit of a function, branches and `return` included, and a linear `invariant` (or `where` after a field) at every construction of the tuple, from the same facts as a call. A condition that can never hold there is a compile error; an unknown one says nothing (the run-time check stays) unless `prove = true` makes it an error; only parameters get a note. Tests that built a bad value on purpose to see the run-time abort now hide the value from the checker. `tests/run_proveexit.py` covers it.

`io.Buffer` can rewind and seek (`ref b.rewind()`, `ref b.seek(n)`, and `io.position(b)`), so what was written can be read back. Lesson 62 now says that Reader, Writer and Cont are the transformers over `Identity`, and the intros no longer say an unprovable `where` is a compile error.

Contracts and refined parameters share one rule for "unknown". When the solver can neither prove nor refute a `where` condition, the call compiles with a note and the condition (also a `requires`) is checked at run time; `[contracts] prove = true` in `Moxie.toml`, or `--prove`, makes it an error as before. A refuted condition is an error either way. `tests/run_unknown.py` covers both modes; lesson 49 and the Spec say so. Also new: `where` after a result type is an `ensures` (`fn abs(n Int) Int where result >= 0`) and after a tuple field an `invariant` (`balance Int where balance >= 0`), with Spec 9c opening on the one-mechanism view and lesson 55 "One condition, two spellings". Results and fields are run-time checks for now; proving them at compile time is future work. `tests/run_wherepos.py` covers them.

`FreeT` removed. `FreeT`, `FreeStep`, `MonadFree`, `fold_free_t`, and `lift_free_t` are gone from `fp.trans`; `fp.freer` (lesson 42) does the same job without a `Functor` per command, and a handler can return an inner-monad value to get effects. Lesson 63, the moxie/gc Spec, and INTERPRETER.md are updated.

`State`, `Reader`, `Writer`, and `Cont` are transformers over `Identity`. `fp.state`, `fp.reader`, `fp.writer`, and `fp.cont` now delegate to `StateT`, `ReaderT`, `WriterT`, and `ContT` from `fp.trans` (one implementation of each monad), and keep their names and plain results: `State.run(s)` still gives `(result, state)`. New constructors `state`, `reader`, `writer`, and `cont` build one from a plain function, and `Writer`'s `value` and `log` are now methods. Lesson 63 says so.

`readonly String` replaces `static String`. A string that lives for the whole program is now written `readonly String` (it lives in read-only program data); `static` keeps one meaning, a function or property that belongs to a type, and `static String` is a syntax error that says so. Spec, intros, lessons and the guide corpus are updated.

The `io` package. `io.Reader` and `io.Writer` are the byte-stream interface pair (`read(ref self, n)`, `write(ref self, bytes)`), implemented for files and sockets, `stdin`/`stdout`/`stderr`, and an in-memory `io.Buffer`, with `io.say`, `io.copy` and `io.read_all` generic over them. `write_bytes` now works on `stdout` and `stderr`, and `ref r.read(n)?` parses. Lesson 63 is new (byte streams) and the later lessons moved down one. `tests/run_io.py` covers both dialects.

Backtick infix removed. ``a `f` b`` is gone (the lexer says so and points to `f(a, b)` or `a |> f(b)`); it came from Haskell and a call or a pipe says the same thing. The grammar, both specs, both intros, and lessons 21 and 50 are updated.

`ref self` methods. A method declared `fn add(ref self, x Int) Unit` rebinds its receiver, and the call says so, `ref m.add(1)`, like any other `ref` argument; it works in interfaces and through generic bounds, and leaving the `ref` off (or adding it to an ordinary method) is a compile error. `tests/run_refself.py` covers both dialects.

Removals. Four overlapping or special-purpose features are gone: **operator sections** (`(+ 1)`, `(10 -)`, ``(`f` 2)``, `(in xs)` and the whitespace rule for `(- 4)`; a placeholder says the same, `_ + 1`, `10 - _`, and the error points to it), **the `<~` operator** (`~>` composes left to right; `~` on a function is now a compile error that says so), **`fp.free`** (`fp.freer` stays, and `FreeT` in `fp.trans`), and **two corners of GADTs**: a case of an enum with a header can't state its own result type, and a case's own type variables must be declared in brackets (`Pair[A, B](a Value[A], b Value[B]) Value[(A, B)]`) instead of being picked up from one-letter names. `Has[X]` bounds, `ref` parameters, and field delegates stay.

Bareword Dict keys are gone. In a `Dict(...)` literal, in `d(k)` and in `d(k) = v`, a name is always a variable, so a word key is written as a string (`"alice" -> 30`, `ages("alice")`). Before, `alice -> 30` meant the string key and `$who` marked a variable, which read the opposite way from the rest of the language. The `Dict(age, n)` shorthand that used a variable's name as the key is gone too (`"age" -> age`), and `{a, b} -> (1, 2)` takes strings or expressions. A tuple's `t(name)` still names a field, and `$name` is still accepted in a Dict lookup. The Specs, lesson 17, the intro, and the tests are converted.

A language server. `moxie lsp` speaks the Language Server Protocol over stdio: the errors and warnings of `moxie check` as you type, Format Document with the `moxie fmt` layout, and an outline of the declarations (`moxie/lsp.py`, tested by `tests/run_lsp.py`). The VS Code extension in `tools/editor/vscode-moxie` now starts it (run `npm install` there once), and the Vim README has a Neovim snippet. Neither client has been run in a live editor yet, and hover types, completion, and go to definition are not there yet.

The Mixer's Guides are retired. They moved to `archive/` and are no longer published or linked; the Mixer’s Guide is the teaching guide, the Spec and the Tutorial point to it, and the nav of both sites lists it in their place.

Tail calls, `deriving show`, and the Mixer’s Guide's 64 lessons. A call in tail position of a function that calls itself now runs as a loop in constant stack (it was only for `tailrec fn`; `tailrec` still makes a non-tail self-call an error), and a runaway recursion stops with a "stack overflow" diagnostic instead of a Python traceback. Deep tail recursion used to slow down quadratically (a finished `Done` raised StopIteration, which costs the depth of the generator stack); it is now linear. Printing or interpolating a declared tuple or enum without `deriving show`, `impl Show`, or a `show` method is a compile error that says what to add (package and prelude types are exempt); about 80 test files and four intro examples got `deriving show`. Variadic arguments are now type-checked one by one. `3 km` stays an Int when the unit scale is whole (`3 km in m` prints `3000`). The Mixer’s Guide now has 64 lessons: input and files, builders, JSON, regex, statistics, networking, units, SQL, the functional-programming sequence (functors and monads, for comprehensions, state and lenses, tagless final, open data types, the free monad, GADTs and typestate), receiver blocks, typeclasses, types that compute, properties and delegates, refined parameters, contracts, mutable blocks, session types, pools and memory, calling C, `fmt` and locales, a lesson for imperative programmers, a side-by-side of the two dialects, more stream tools (`unfold`, custom sources), reader, writer and continuations, transformers, and a closing page. A declared tuple or enum without a text form is also called out in both Specs. Lesson cross-references use the numbers on the pages, which is the position in `lessons/_toc.txt`; if you insert a lesson, renumber them.

The Mixer’s Guide, the teaching guide (started). A lesson-by-lesson course, one page per lesson, in both dialects from one source (`lessons/`, built by `tools/make_learn.py` into `docs/learn/` and `docs/gc/learn/`). No exercises: detailed explanation and many complete examples, each checked by `tests/run_learn.py` (output blocks and expected compile errors, both dialects). It will replace the Mixer's Guides when it covers everything they do. First seven lessons: running moxie, a first program, values and names, numbers, text, truth and choices, loops. Fixes found while writing: a `Char` range (`'a'..'e'`) can be walked in a `for` (it was refused as a range of strings), and the REPL results are `$res1`, `$res2` (the intros said `res1` and `it`).

Small unit leftovers. The files of a multi-file package now share its units (a unit declared in one file is in scope in the others; a derived unit comes after its base in the manifest's order). Scaled conversions are rounded to 12 significant digits, so `2.01 km in m` prints `2010.0` instead of `2009.9999999999998`. `run_wrappedif.py` error cases now expect the `block` message. Cases in `run_unitpkg.py` and `run_units.py`.

Blocks of children, the last design item. A function marks its last parameter `block` (`fn ul(class String, block items List[Li]) Ul`), and a call followed by an indented block fills it: each line is a child, `if`/`elif`/`else` and `for` add children conditionally or per element, `...list` adds a list, and a binding adds nothing. The block is rewritten by the parser into list concatenations, so the existing typing and capacity rules apply (`tests/run_block.py`, 38 cases). Spec 9b and section 25, and Guide chapter 21 (gc: 22).

Set algebra, from the F# and Swift survey. `Set` had `+` (union); it now has `-` (difference, or one element removed), `&` (intersection), `^` (symmetric difference), and `is_subset`, `is_superset`, `is_disjoint`. The survey (F# 9 and 10, Swift 6 to 6.3) found nothing else moxie lacks except a block form that collects children for DSLs, the open item in Spec section 25.

Units: spread typing, unit parameters, packages. The checker now types the names bound by a spread in an enum payload pattern (`Circle(radius: r, *more)`: `r` has the field's type and `more` the leftover fields). A function can be generic over units (`fn twice[U](x Double[U]) Double[U]`, `Double[A/B]`, `Double[U^2]`): a call binds `U` to the argument's dimension and the result uses it. A package can `export unit m`, and `import` brings its units into scope, so `5.0 m`, `d in km` and exported signatures such as `Double[m/s]` work across packages (`tests/run_unitpkg.py`, plus new cases in `run_units.py` and `run_tuplespread.py`).

Design language. Moxie is now called a design language wherever it introduces itself: both intros, both Specs, both Guides and this README say that it is a language design (a specification and a reference interpreter), not yet a production compiler.

Sized integers keep their width through inference. The checker used to give every `Int8`..`UInt64` the one type `Int` and kept the written width in a side note on variables, so a width reached through a generic call, a method of a generic tuple, a field of a generic tuple or a loop variable was lost and `first(xs) + u` (an `Int8` plus a `UInt8`) went unchecked. The width is now part of the checker type (`tys.Sized`, which still compares as `Int` everywhere else), so every route carries it and Spec 3's mixed-number rule is enforced on all of them. Methods of generic tuples now also have their result typed. `tests/run_numeric.py` has 18 new inference cases.

Intro pages. "Get it running" now keeps the typed-in lines flush with the text (no stray restarted numbering), the "On a Mac" section became a terminal section for macOS, Linux and other Unix, with a note that Windows is untested, and the Immutability section says to read `x = 5` as a statement of equality, as in math.

Dialect names. Internally, in notes, tests and commit messages, the GC-free dialect is **moxie/nc** ("no collector") and the collected one is **moxie/gc**; the site pages and the specs keep saying "moxie" for the default dialect and "GC-free moxie" where the contrast matters.

Newest first.

**2026-11-20 (literal folding, Dict order):** the checker folds `abs`, `min`, `max`, `clamp`, `pow`, `len`, `floor`, `ceil`, `sqrt` on literal arguments (`const_eval`, `fold_builtin`; a program-defined function of the same name is never folded), so `6 / abs(0)` is a compile error and `Array[Int][abs(-3)]` is a size 3; no variable is tracked. Two constant keys that repeat in one `Dict(...)` (no `...spread` between) give a warning. `Dict(...)` entries are now added strictly in the order written: labeled entries (`a -> 1`) used to be applied after the computed ones (`(k) -> 2`), so `Dict(1 -> "a", (1) -> "b")` kept `"a"`. `tests/run_dictkeys.py` (56), specs, guides.

**2026-11-21 (`*` spread):** in a pattern `*rest` and a bare `*` are a short spelling of `...rest` and `...` (lists, tuples and dicts; destructuring too), so `(status: "ok", items: List((id: f, tags: List(a, *o), *e), *rem), *top)` reads like Python's `*`/`**` patterns. `...` still works, and `*` is still multiplication outside a pattern. A pattern can already be broken over several lines inside its parentheses. `tests/run_tuplespread.py`.

**2026-11-21 (tuple spread):** `...rest` in a tuple pattern now binds a labeled tuple of the fields the pattern left out: `Item(id: i, ...rest)` gives `rest` the other fields, `(id: j, ...more) = (id: 7, name: "x", age: 3)` gives `more` as `(name: "x", age: 3)`. It used to bind a list of every field, and a bare labeled destructuring left the name unbound. Lists and dicts are unchanged. The checker types the names too: in `Item(id: i, ...rest)` or `(id: i, ...rest)`, `i` has the field's type and `rest` the exact type of what is left, so `rest.nme` and `i + "x"` are compile errors, and a label the tuple lacks is an error (the pattern can never match). `tests/run_tuplespread.py`.

**2026-11-20 (type declarations):** the `type` forms are unified with associated types (`type Item = String`): `type Pos = Int` is an alias (`where` refines it), `opaque type Id = Int` hides its representation, and `union type Key = Int | String` is a union (`union type One[A] = Say[A]` for one member; a bare `type X = A | B` is an error that says so). `type alias X`, `type opaque X` and `type union X` are errors that say what to write. `opaque` and `union` are soft modifiers that count only before `type`, so `union(a, b)` is still a call. `enum`, `tuple` and `interface` are unchanged. Every guide, spec, test, example and the std library was migrated by a script. `tests/run_typedecl.py`.

**2026-11-20 (mixed numbers):** a value widens implicitly only when every value of its type fits the other side (Spec 3): `Int8 + Int16` is an `Int16`; `Int8 + UInt8`, `Int64 + UInt64` and `Int + Double` are compile errors that ask for a `cast`; literals adapt (`x * 2`). An `Int32` or narrower mixes with a `Double` (it is exact), at run time too (it used to abort). Checked for variables and parameters with a written width, suffixed literals, and any `Int` with a `Double`; widths are tracked through variables, parameters, suffixed literals, tuple fields, function result types, `List[Int8]`-style elements and bindings made from them; a width that only inference knows (generic results, method results) is a known gap. The same rule now applies when a value is bound to a written type or passed as an argument (`e Int8 = d` with `d Int16` is an error; an `Int8` for a `Double` parameter is fine; `Int` to `Double` was already an error there). `tests/run_numeric.py`, spec 3.

**2026-11-20 (units of measure):** `unit m` declares a unit, `unit N = kg * m / s^2` derives one, `5.0 m` is a quantity, and `Double[m/s]`, `Int[m^2]`, `Double[(m/s)^2]` are types. The checker works units through `+ - * /` and comparisons (`1.0 m + 2.0 s` and `1.0 m + 2.0` are errors, `m / s` is `m/s`, `m / m` is a plain number) and through `abs`, `min`, `max`, `sum`, `clamp`, `floor`, `ceil`, `round`, `sqrt` (halves) and `pow(x, 2)`; `product` of quantities is refused and `magnitude(q)` drops the unit. Units are erased at run time, `Duration` and its literals are unchanged, `5s` is still a Duration and `5 s` a quantity once `unit s` is declared. Scaled units: `unit km = 1000 m`, `unit mile = 1609.344 m`, `unit kmh = km / h`; a scaled unit has its base's dimension, quantities are stored in the base unit (`5.0 km` is `5000.0`), `d in km` converts out (`in` before a declared unit; `d / 1.0 km` still works), and an `Int` amount must be a whole number of base units. No Celsius/Fahrenheit (offset scales). Not yet: generic unit variables. `moxie/units.py`, `tests/run_units.py`, guides (Chapter 30 / 31), specs (23g), intros, grammar.

**2026-11-20 (Dict keys):** in a `Dict(...)` literal, an expression followed by `->` is now a key: `abs(-3) -> 1`, `Color.Red -> 1`, `Key.ById(7) -> 1`, `$k -> 1`. Before, a call followed by `->` was read as a call with a trailing lambda, so `Dict(abs(-3) -> 1)` silently made an empty Dict and `Key.ById(7) -> 1` aborted. A capitalized bare name (`Red -> 1`) is a value, not a string, so enum keys work (also in `{Blue, Red} -> (3, 9)`); lowercase bare names stay strings. Every stage (`map`, `filter`, `take`, `sort`, `zip`, `enumerate`, ...) is lazy and returns a `Stream`; only `collect()`, a terminal (`sum`, `count`, `reduce`, ...) or `for` converts, so nothing is inserted behind your back. `to_stream()` is now only for passing a collection where a `Stream[T]` is declared. `map` is always the stage; the container-preserving Functor method is `fmap` (`List -> List`, `Array -> Array`, `Option`/`Result` unchanged), and `<$>` and `for:` comprehensions use it. `xs.map(f)` therefore needs `|> collect()`; use `xs.fmap(f)` to stay a List.

**2026-11-17 (fill):** `fill(value)` now fills a declared `Array`, `List` or `MultiArray` (`a Array[Int][3] = fill(7)`).

**2026-11-17 (when arms): `in` and `not in`.** A range arm in a `when` is written with a leading `in`: `in 1..9 step 2 ->`, `not in 0..<100 ->`, `in lo..hi ->`, `in xs ->`. That removes the `n if n in ...` guard boilerplate. A bare range arm (`1..<9 ->`) is now a syntax error that points to `in`. Literal-bound arms still count toward coverage. `start(r)` is gone: `first(r)` and `last(r)` give the first and last values a range reaches (a `Result`, an error for an empty range), alongside `limit(r)` and `step(r)`.

**2026-11-17 (ranges): `a..<b step s`.** A range takes a step after its bounds, as in Kotlin: `for i in 0..10 step 5`, `10..<1 step -3`, `3 in 1..9 step 2`, `xs(0..8 step 2)`, `1.. step 5`, and a stepped range is also a `when` arm pattern. The step is signed and its sign decides the direction with literal or variable bounds; a literal wrong-way step (`10..<1 step 3`) and a zero step are compile errors, and a variable-bounds wrong-way step is empty. `step` is a soft keyword only directly after a range (32nd soft keyword). `Range(a..<b, s)` is gone, with an error that points at the new form, and every use in the specs, guides, intros and tests was rewritten. Also: `in` now honours the step (it used to ignore it, so `4 in 1..9 step 2` was wrong), stepped slices pick every nth element, `len(range)` works, `indices(xs)` is `0..<len(xs)`, `clamp(x, 0..100)` takes a range, and `random_int(1..6)` takes a range instead of two numbers (the two-number form is an error that shows the new one). The debts list in both intros is trimmed of parenthetical asides and credits Kotlin for `step`. 22 tests in `tests/run_ranges.py`.

**2026-11-17 (docs pass).** Chapter 14 of the gc guide (and the wording of the no-GC one) now says what caching moxie has: nothing is automatic, `lazy` bindings, properties and parameters evaluate once, and the recipes are a bottom-up `reduce`, a `Dict` threaded as `ref`, and **[gc]** a `memoize` wrapper over an `Atom` (new, tested example). The intros say where `mutable` fits in the immutability fine print, and the gc texts now say that in moxie/gc the in-place guarantee of a `mutable` block applies to `Array` and `MultiArray` (their updates copy elsewhere) while `List`, `Dict` and `Set` keep persistent updates. New check: `a(i) = v` or `p.x = v` in a nested block on an outer `a` or `p` (without `@1`) is an error, like `total += x`; before, it silently changed a copy and the outer value stayed the same.

**2026-11-17 (latest): `select` arms lose `case`.** A `select` arm is now written like a `when` arm or a `seq` stage, `head -> body`: `v = read(ch) -> ...`, `closed(ch) -> ...`, `cancelled(c) -> ...`, `_ -> ...`, and a final `else body`. The old spelling (`case v = read(ch) ->`) is a syntax error that shows the new one, and `case` is an ordinary name again, so it leaves the soft-keyword list (31 now). Every select in the specs, guides, intros and tests was rewritten, and the guide corpora regenerated with no expected output lost. One more behaviour found while doing `mutable`: assigning to an outer name that is not on the block's `in` line used to change a local copy silently; it is now an error that says `in a`.

**2026-11-17 (later): `mutable` blocks.** Taking Haskell's reason for `ST` (fast imperative algorithms inside a pure function, contained so the caller sees a pure function), moxie gets a `mutable` block: the names it declares are mutable variables, `x = e` declares the first time and assigns after that, and `x += e`, `x(i) = e`, `x.f = e` write into the variable from any depth of loop or branch, with no `@N`, no shadowing, and a fixed type per variable. An `in` line copies outer values in; other outer names are read-only; `b = a` inside copies; the block is pure from outside, so a `pure fn` may contain one. In the reference interpreter it is a rewrite to `x@1` assignments (the in-place guarantee is the compiler's contract); 9 tests in `tests/run_mutable.py`. `mutable` is the 32nd soft keyword. The gc spec was missing the `eval` bullet and had a stale soft-keyword list, both fixed.

**2026-11-17: "Encapsulating state without objects", and `eval pure`.** A new section in both intros, after "Modularity without classes", maps the five FP ways of hiding state onto moxie: `type opaque` for invariants, `ref` threading (and `fp.state` in moxie/gc) for State, local mutation (moxie needs no `ST` monad, because values are immutable and have one owner, so an in-place update cannot escape), and `any Interface` as the existential, with a summary table. `eval pure` is accepted as the explicit spelling of a plain `eval`. **2026-11-15: `with` capture layouts are checked everywhere.** A parameter, a result (the closure the body returns, inline or held in a local), a channel element, a tuple field and a collection each hold only closures of the layout written. A function name or a lambda that captures nothing has the empty layout, so it is refused where `with (Int)` is written, and a closure that captures values is refused in a slot written without `with`, whether it is written there or held in a variable. Mismatch messages say which side captures what.

**2026-11-15: `update` lines take commas and `&`; `do` has no `->`.** In `x.update`, a comma ends each line except the last, as in a constructor call (a trailing comma is allowed, and a missing one is a compile error). `&` in a right-hand side is the field's current value, so `retries: & * 2` doubles it without repeating the name; a `&` that is the slot of a pipe stage keeps its pipe meaning. The one-line `x.do -> expr` is gone: `x.do` takes its block on the lines below, since `->` belongs to lambdas, Dict entries and arms. A line that ends in a comma and is followed by a dedent now dedents instead of joining the next statement. Spec 9b and the Guide (8a) updated.

**2026-11-15: closures of one capture layout can be stored (moxie).** A written function type may end in `with (T1, T2)`, the types its closures capture (`(Int) -> Int with (Int)`; the order doesn't matter). Slots written that way (tuple fields, collection elements, bindings, parameters) hold closures with exactly that layout. In a literal with no written type, the first capturing closure sets the layout and the rest must match (a closure that captures a different kind of value is an error), and so does an update like `t("y") = ...`. A type written without `with` still takes plain functions only. Spec 11, the Guide and the intro updated.

**2026-11-15: constants are not captures.** A name bound once, to a value the compiler can work out, is a constant, so a lambda that uses only constants, parameters, and its own locals captures nothing and counts as a plain function (it can be stored in a Dict, List, tuple field or channel in plain moxie). This now holds for locals inside a function, not just module-level names. A name bound more than once, including an entry-file name that is later rebound, is a variable and is a capture. Spec 11 and the Guide updated.

**2026-11-15: anonymous `fn`s have no `->`.** Only a lambda uses `->` in its declaration. An anonymous `fn` is written like a named function with the name left out, `fn (params) Ret`, with the body indented below, and an inline fiber is `go fn (args)(params)` with an indented body (or the short form `go fn (tx)` when each parameter has its argument's name). The old `fn (...) -> body` form is a compile error that points to the new one. Because a block can't sit inside a call's parentheses, an anonymous `fn` is bound on its own line and passed by name. The effects checker now follows a bound anonymous `fn`: calling it, or passing it to a function that calls it, carries its effects (a pure function that calls one that parks is now caught). Tests, Spec, Guides, intros and tutorials updated.

**2026-11-15: capturing closures in collection literals.** A capturing closure written inside a `Dict(...)`, `List(...)`, `Set(...)` or `Array(...)` literal is now the same compile error as in an annotated slot (moxie only; moxie/gc stores it). It used to slip through. Module-level names aren't captures.

**2026-11-15: several Dict entries at once, and tuple keys in literals.** `Dict(...ages, {alice, bob, dave} -> (31, 26, 7))`: braces mark a list of keys, and a tuple of values pairs with them by position, so a count mismatch is a compile error. A tuple on the left of a plain `->` is one key, so `Dict((0, 0) -> "start")` works; before this a tuple-keyed literal silently produced an empty Dict.

**2026-11-15: a Dict spreads into a Dict literal.** `Dict(...ages, alice -> 31, dave -> 7)` copies the old entries first, in order, then applies the new ones: a key already there is replaced in place, a new key goes at the end. Before this, `Dict(...d)` silently dropped the entries of `d`. Also fixed today: a `wait` block (and a `select` with no `default`) crashed the Try page's permission check with `KeyError: 'parks'`.

**2026-11-15: `scope` is now `wait`.** The structured-concurrency block that waits for every fiber started inside it (and can bind a `Cancel` token) is written `wait`, or `wait token`; "scope" now means only the layers of bindings that `name@N` counts. The old spelling `scope` is an error that points to `wait`, and `wait` stays a legal name anywhere that is not a statement-start block.

**2026-11-15: the `in` line.** The first line of a block can be `in total, count`: each becomes a local that starts as the outer value, so `total += x` in a loop body no longer needs `@1` and no longer trips the shadowing error. `in total@2` and `in total@serve` pick a layer or a labeled loop. In a loop the copy happens once; later passes carry the value. The local ends with the block: leave with `break(total)` or `else total`, or write `total@1 = ...`.

**2026-11-15: `name@label`.** A label names the scope that `name@N` would count: `total@serve += x` inside `#serve for ...` writes the `total` bound outside that loop, however many blocks lie between. Works for any labeled loop or `do`; an unknown label is an error. A label starts with a lowercase letter, so `p@Product(...)` stays an as-pattern.

**2026-11-15: `moxie run` prints warnings.** The compiler's warnings (a shadowed name, a dropped `Result`, and the rest) used to appear only under `moxie check`. `moxie run` now prints them on stderr before the program starts, in the same `file:line: warning:` form, and they never change the exit code. `--quiet` and `--release` leave them out. The Try page shows them above the program's output.

**2026-11-15: no more `total = total + x` that quietly does nothing.** In an inner block (a `for` body, an `if`, a `when` arm), a line that defines a name and also reads the same name from outside (`total += x`, `total = total + x`) is now a compile error, since the new `total` would vanish at the end of the block and the outer one would never change. The message says to write `total@1 += x`, or fold with `reduce`. A plain shadowing line like `x = 5` still only warns. Loops may still carry state on purpose: a name their `while` condition reads, one their `break(value)` or `else` hands out, and the state of a `daemon`. A name carried only for the condition and then read after the loop is an error too. Tests in `tests/run_shadow.py` and `tests/run_gimme.py`.

**2026-11-15: `name@N` replaces `gimme.N.name`.** `total@1` is the nearest enclosing block's `total`, to read or to write (`total@1 += x`), and `n@2` is the next one out. The old spelling is now an error that shows the new one, `gimme` is no longer a soft keyword (30 left), and the Spec, Guide and tests use the new form. At the start of a statement, `name@<number>` is this reference, not an as-pattern with a number; `p@Product(...)` is unchanged. Tests in `tests/run_gimme.py`.

**2026-11-14: chained casts.** `[A : B : C](x)` casts to `C` first, then `B`, then `A` (`[Char : Int](65)` is `'A'`). Each step can abort, and a constant that does not fit a step is a compile error. Only in the bracket sugar; `cast[...]` takes one type, and a file may not mix `cast[T](x)` with `[T](x)` (a compile error naming the other line). Tests in `tests/run_castsugar.py`.

**2026-11-14: `[T](x)` for `cast[T](x)`.** A type in brackets followed by an argument in parentheses is sugar for `cast`, with the same abort and the same compile error for a constant that cannot fit. The docs keep spelling out `cast`; `try_cast` and `wrap_to` have no short form. Test: `tests/run_castsugar.py`.

**2026-11-14: refined aliases.** `type Pos = Int where self > 0` names a condition. A parameter declared with it (`fn half(n Pos) Int`) is a parameter with that `where`, so each call proves it, and a `Pos` parameter in the caller counts as a fact. Only parameters are checked, since the alias is still an `Int`. Spec 9d, Guide 9c, tests in `tests/run_refined.py`.

**2026-11-14: refined parameters.** A parameter may end with `where cond` (`fn get(xs List[Int], i Int where i >= 0 and i < len(xs)) Int`), and every call must prove the condition. A small built-in solver (integer linear arithmetic, exact) reads the facts the code gives it: the caller's own `where`, `if`/`elif`/`else` tests, early returns, `for i in 0..<len(xs)`, names bound to a sum or difference, constants, and bounded integer types. Proved compiles, refuted and unknown are errors that name the condition. The condition is also kept as a `requires`, so a call through a function value is still checked at run time. Spec 9d, Guide chapter 9c, `tests/run_refined.py`. Not yet: refined type aliases, results, and tuple fields.

**2026-11-14: operator sections.** `(+ 1)`, `(10 -)`, `(* 2)`, `(> 2)` and ``(`f` 2)`` are one-parameter functions, the same as the placeholder forms. Subtraction follows whitespace inside the parentheses: `(-4)` is the number and `(- 4)` is the section, so there is no `subtract`. Test: `tests/run_sections.py`. The Spec and both intros no longer say that moxie has no sections.

**2026-11-14: `impl` members can leave out their types.** `fn info(self, msg)` is enough when the interface already says `msg String` and `Unit`; the compiler copies the types. The parameter names must be the interface's (Steve's rule, so a labeled call means the same on the type and through the interface), and a different name is an error. A label that names no parameter of a method is now a compile error, not a run-time abort. Covers your own interfaces and the built-in `Show`, `Read`, `Equatable`, `Ordered`, `Addable` and `Numeric`. Written types are still allowed and checked. Ordinary functions still need theirs. Test: `tests/run_implsig.py`.

**2026-11-14: one code for "not there".** `get(xs, i)` on a List or Array and `Enum.from_index(n)` now give `MISSING` (4), as a Dict key, `first` of nothing and `value_of` already did; they used to give `OUT_OF_RANGE` (6). **2026-11-14: let-else can see the failure.** `Ok(n) = read[Int](t) else Err(e) -> Err(wrap(e))`: the else takes a pattern of its own, so the `Err`'s code and message are in scope (to log, to convert). The two patterns must cover every case together, as in `when`, and the old `else value` form is unchanged. Guide chapter 12, Spec section 1, `tests/run_letelse.py`.

**2026-11-14: `dynamic fn`, `unsafe fn`, `deriving dyn`.** Reading a `Dyn` (`field`, `at`, `as_*`, `from_dyn`) now has to happen in a function marked `dynamic fn`, and calling a foreign function marked `unsafe` (or taking a `Ptr[T]`) in one marked `unsafe fn`; unmarked use is a compile error, top-level script code is exempt, and `dynamic`/`unsafe` stay usable as variable names. Only the function that does the thing is marked, so a checking wrapper can be called from anywhere; `safety = "strict"` under `[program]` in `Moxie.toml` makes callers carry the mark too. `deriving dyn` on a tuple writes `to_dyn()` and a checked `Tuple.from_dyn(d)` (a `Result`, naming the missing key or wrong kind) at compile time from the field types: `Int`, `Float`, `Bool`, `String`, `List` of those, and nested tuples that derive it. Guide chapter on JSON, Spec 23c/23d, `tests/run_safety.py`.

**2026-11-14: `proxy`.** `impl Printer for Logger proxy(printer)` hands a whole interface to a field: the methods the block doesn't write forward to the field, so only the ones that differ are written (Kotlin's class delegation). Guide chapter 9a. Plain methods of an interface declared in the same file only; `static`, `ref`, generic and `Self` members are errors that say to write them by hand.

**2026-11-14: Three more mistakes caught at compile time.** A pattern that can never match its value (`Some(n)` against a `Result`) is an error, in `when`, `is` and let-else. Dropping a `Result` as a statement is a warning (write `\ call()` to drop it on purpose). `cast[UInt8](300)` of a constant that does not fit is an error.

**2026-11-13: Union elements and `elif` chains.** The loop variable over a list of a union is a union (`for x in ids`, then `x + 1` is an error until tested), and so is `ids(i)`; `if ids(0) is Int` narrows that element. An `if`/`elif` chain in which some arms leave now narrows what follows, from the arms that stay.

**2026-11-13: Narrowing after an early exit, and with `not` and `or`.** `if not (v is Int) then return 0` now makes `v` an `Int` on the following lines; `break`, `continue` and the guard forms work the same, as do field paths. `not` and `or` narrow, and a test that leaves several members leaves a union of those. A branch that doesn't leave narrows nothing after it. `==` never narrows.

**2026-11-13: Union values are checked.** A value of a `type union` is one of its members, so using it as one (`v + 1`, `len(v)`) is now a compile error until `is` or a `when` says which. `if v is T` narrows the then-branch, each `elif`, the `else` when one member is left, the right side of `and`, and field paths (`p.f`). `println`, interpolation, `==` and passing the union on need no test. Before this the checker let any use of a union through.

**2026-11-13: Bare tuples.** A function can end with `a, b` (or `return a, b`) instead of `(a, b)`, matching `lo, hi = f()`.

**2026-11-13: `json` package and `Dyn`.** `import json` gives a closed `Dyn` enum with `json.parse(text)`, `d.field(key)`, `d.at(i)`, `as_int()` and friends (all `Result`), and `to_json()`. It is written in moxie, uses no reflection, and works in both dialects. Conversion to and from your own types (`deriving dyn`) and the `dynamic fn` marker are not built yet (FIXLIST).

**2026-11-13: Chained comparisons.** `0 <= x <= 100` means `0 <= x and x <= 100`. Any run of `<`, `<=`, `>`, `>=` and `==` chains (`a == b == c` means all equal); a middle operand is evaluated once and the chain stops at the first false link. `~=` does not chain (an error says to use `and`). `(a < b) == flag` now needs its parentheses.

**2026-11-13: Loop `else` is checked.** The Spec already said a `for` or `while` that uses `break(value)` needs an `else` of its own, but the checker accepted a loop without one (including one whose `else` was indented so it belonged to the `if`). It is now an error. The Guide points out that a loop's `else` lines up with the loop.

**2026-11-13: Chained bindings.** `x = y = z` binds `z` to `y` and then `y` to `x`, and the names may be lined up one per line with each `=` ending its line. The Guide gains a section on binding several names at once (section 1f), and "assignment" is now "binding" or "update" throughout.

**2026-11-13: Wrapped guards.** The condition of a trailing `if` may go on its own indented line under the action, for a condition too long for the line: `action` then `  if cond` means `action if cond`. A guard may also end with `else value`: if the condition fails the action is skipped and the function returns the value, like a let-else (`println("loading") if ok else fail(1, "bad")`).

**2026-11-12: Colonless syntax.** Blocks no longer start with a colon, and declarations put the type after the name (`x Int`, `fn f(x Int) Int = x * 2`). Typed bindings read the same way (`total Int = 0`). Dict entries use `key -> value`. `(:40)` is a one-item tuple, shorthand for `(0: 40)`. A bare name after a named argument is a pun for `name: name`. Colons stay in values: `User(name: "Al")`, `(x: 1, y: 2)`, `update` lines. The old syntax is on the `oldmain` branch.
