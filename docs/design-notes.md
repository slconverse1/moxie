# DESIGN NOTES MOXIE

The decisions behind the language, kept by date. They are a record of what was decided and when, and the wording of an early note may be older than the language: the [Spec](spec.html) is the reference for what moxie does now.

## Decisions recorded on 2026-11-01

- String slices count bytes, and a cut inside a multi-byte character aborts.
- `return` inside a lambda leaves the lambda.
- `clone` stays out of loops, as a starting rule.
- In partial type application the hole is the first type argument (`Result[_, E]`).
- Enum cases print with their type name (`Shape.Circle(10)`).
- `<$>` and `<*>` sit in the comparison precedence tier, so mixed chains are parenthesized.
- An impl that overrides a default method replaces it wholesale.

## Decisions recorded on 2026-11-02

- The prelude gets `distinct`, `intersperse`, `flatten`, `min_by`, `max_by`, `span`, and `split_at`, and `zip_with`, `reduce_right`, and `cycle` are settled.
- A function clause may carry an `if` guard, and `tailrec fn` makes a non-tail self-call an error.
- Doctests are designed in outline, and `moxie fmt` has its layout and spacing rules built (section 22).
- `moxie doc` generates documentation from `///` comments, including each item's contract and inferred effects (section 22).
- Contracts are designed in outline (section 9c): `where` on parameters and results of free functions, extension functions, and interface members, `invariant` on tuples, checked in debug builds and `moxie test`.
- An abort in any fiber ends the program, so moxie has no supervisors, links, or restarts. A test block's abort fails only that test.
- Multi-core scheduling is ruled out, since moxie's freedom from data races depends on one fiber running at a time.
- Contracts: a postcondition sees a `ref` parameter's final value only, the release key is `keep_in_release`, an `impl` adding contracts is a compile error, and a failing constant precondition is a compile error.
- Active patterns (`pattern fn`) and units of measure were dropped at first and are now in the language. `NonEmpty` is added to the prelude, and binary patterns are sketched in section 8.
- `moxie doc` marks an effect as declared (a promise to callers) or inferred (not promised), and `--check` warns about an exported function with no effect declaration.
- `curry(f)` works for any number of parameters, and `uncurry[n](g)` is its inverse with the count written in brackets; each is a compiler-known function with its own typing rule, so no parameter packs are needed (section 11).
- Foreign functions (section 19a): a `foreign "lib"` block of body-less declarations with required, trusted effect declarations; scalars, tuples of scalars, byte arrays as pointer and length, `ref` out-parameters, and opaque handles as resources cross the boundary; callbacks only for the length of a call; `parks` calls run on an OS helper thread; only a package with `[native]` may declare them; `moxie bindgen` generates the declarations.
- `[native]` read (2026-11-04, section 19a): `libs` limits the libraries a package may name and `paths` are searched first; a manifest with no `[native]` refuses `foreign` in its package, and a missing manifest does not.
- FFI handles (2026-11-03): `handle Name closes fn` inside a `foreign` block declares an opaque C pointer as a move-only resource. A function returning one is declared `Result[H, Error]` (NULL is `Err(MISSING)`) or plain `H` (NULL aborts). The closing function consumes the handle (later use is a compile error); a handle left open is closed when the program ends. `moxie bindgen` declares handles and finds the closing function by name or from `[handles.NAME] closes` in `bindgen.toml`. Out-parameter handles, the pool tally, and callbacks remain open.
- Standard input and output (2026-11-03, section 19b): `stdin`, `stdout`, `stderr` are borrowed runtime-owned values (never moved or closed); `print`/`println` take an optional stream first; `eprint`/`eprintln`, `flush`; `read_line()` (Result, `CLOSED` at end of input), `read_all()`, `stdin_lines()` are `parks`; UTF-8 only with a new reserved code `BAD_ENCODING`; `with_stdin(text, f)` for tests. Stdin is ambient (permissions parked); binary I/O is undesigned.
- Files and sockets (2026-11-03, section 19c): one resource type `Io` for files, sockets, and the standard streams; `open_file(path, mode)` with prelude enum `FileMode` (`ReadOnly`, `Create`, `Append`, `ReadWrite`), `read_file`/`write_file`, `connect`, `listen`/`accept`; new reserved codes `NOT_FOUND`, `DENIED`, `IO_ERROR`; ambient for now with capabilities left to the permissions design; paths are `/`-separated UTF-8 strings. Moxie assumes no particular operating system (section 1).
- Program arguments (2026-11-03, section 20): arguments stay plain `String`s converted with `read[T]`; typed argument parsing and flag parsing are left to packages, not the language.
- FFI callbacks (2026-11-03): a function-typed parameter of a foreign function is a C callback, valid for the length of the call; the callee runs inline, so such a function cannot be `parks` and the callback must not park; an abort in a callback ends the program when the call returns; no user-data pointer is needed because closures carry context; `moxie bindgen` declares callbacks of plain values. Buffers, user data, and callbacks that C keeps are open.
- FFI callback buffers and user data (2026-11-03): in a callback's function type, `Array[Byte]` followed by an integer type is C's (pointer, length) pair and arrives as one read-only array; `UserData` is C's `void *` user-data argument (hidden from the moxie function, and declared `ud UserData` and omitted by the caller on the foreign function). Callbacks that C keeps, and callbacks that take other pointers, remain open.
- `moxie bindgen --wrap` (2026-11-03): writes `wrappers.mxi` with a default exported wrapper per declared function: `String` for `CString`, library prefix removed from the name, callback types without `UserData` and lengths, and `Result` for an int status (0 is success) with out-parameters. Guesses are listed in the report and corrected in `bindgen.toml` (`returns`, `outs`).
- `bindgen.toml` format (2026-11-03): top-level `lib`; `[functions.NAME]` with `effects`, `skip`, `pair`, `returns`, `outs`, `rename`; `[handles.TYPE]` with `closes`. The file is validated on every run (unknown keys and bad values are errors with a suggestion; entries that match nothing are warnings).
- Callbacks that C keeps (2026-11-03): a parameter `cb Events[T]` takes the write end of a channel (`move tx`); each C call is copied into a message on it, so moxie code never runs on a foreign thread. The callback must return nothing; a full channel drops events (counted and reported at exit); the registration lasts for the rest of the program; waiting fibers are not a deadlock while one exists. `bindgen.toml` gets `keeps = ["cb"]`.
- FFI handle out-parameters (2026-11-03): a `ref` parameter of handle type is a C `H **` that the call fills in and the caller does not supply. The declared result `Result[H, Error]` means C returns an int status (0 is success, other values become the error code, and any handle C left is closed); a plain `H` result ignores C's own result and aborts on NULL. `moxie bindgen` declares `T **` to an opaque type this way.
- Pool tally for files, sockets, and handles (2026-11-03, section 19): `Io`, `Listener`, and each foreign handle type are tallied like connections, one creation per call to `open_file`, `connect`, `listen`, `accept`, or a handle-returning foreign function. The compiler's static tally has a first version (see the next entry); `moxie --pools run FILE` prints the most of each kind that were open at once (files, sockets, listeners, handles, connections, channels, futures, timers, atoms), which the static tally must cover.
- OS helper threads (2026-11-03): reads, `connect`, `accept`, and `parks` foreign functions run on an OS helper thread while their fiber parks; moxie code stays on one thread; while calls are in flight, sleepers and timers run in real time up to the next due one (2026-11-05; before that, virtual time waited for every in-flight call, so a timeout fiber could not fire during a wait).
- Lambdas without `fn` (2026-11-04, section 9): a function with no name is a lambda whatever its size, written `(params) -> body`; `fn (params) = body` is the anonymous function that may have effects (an inline fiber is one). A lambda is a value bound with `=` and a typed name (`add (Int, Int) -> Int = (a, b) -> a + b`), cannot recurse, is not generic, is pure, has no immediately-called form, and takes a builder receiver from its expected type (no `fn Config.()` literal).
- Return type required (2026-11-04, section 9): the checker reports a function with no return type (write `Unit` for none); later clauses of a function take the first clause's. The reference interpreter had accepted and inferred it.
- Parameter types required (2026-11-04, section 9): the checker reports a plain-name parameter of a named function with no type; later clauses take the first clause's, and lambdas keep inferring theirs from context.
- Pool sizes in the budget (2026-11-04, section 3a): `[program] memory` counts the slots of the pools as well as the fibers, with slot sizes by kind and layout sizes for values; a pool whose size is not known cannot be budgeted; the S-space and T-space split is still open.
- `moxie fmt` line width (2026-11-04): a line over 80 columns is broken one bracket group at a time, one item to a line, with the closing bracket on its own line and no comma added or removed; lines with a comment are left alone.
- Effects and permission needs across packages (2026-11-03): calls into imported packages (qualified, imported by name, or UFCS `x.f()` to an impl method) carry the callee's effects and needs; a package's top level counts for needs; per-package ceilings are still checked file by file.
- The pool header at start (2026-11-03, section 3a): `--header=FILE` or `[pools] header`; a hash of the tokens of the program and its packages catches a stale header; the tally follows package calls, package top levels, and fibers started through helper functions; `[program] memory` is a total budget checked as fibers x (`memory` + `stack`); pools and the fiber count are held to the header's numbers. Pool sizes and the S-space/T-space split are not in the budget.
- TLS (2026-11-03, section 19c): `connect_tls(host, port[, ca: path])` and `listen_tls(port, cert, key)` over the same `Io` and `Listener`; the certificate and name are always checked; no options for versions, ciphers, or client certificates.
- UDP (2026-11-04, section 19c): a `Udp` resource with `bind_udp`, `send_to`, and `receive` (a `Packet` of host, port, and bytes, with an optional `timeout:`); one datagram per call, no connection, no `select` arm; permissions are `net.listen` for the bind and `net.connect` for each send; it counts as an `Io` socket in the pool tally.
- Directories and paths (2026-11-03, section 19c): `list_dir`, `file_info` (`FileInfo`), `path_exists`, `make_dir`, `remove_file`, `remove_dir`, `rename_path`, and the text-only `path_join`, `path_parent`, `path_name`, `path_stem`, `path_ext`. Named with a `path_` or verb prefix so that they do not take common names like `exists` or `remove`. A `Path` type, recursive operations, links, and times are left out.
- Per-package permissions (2026-11-03): `[permissions.packages.NAME]` tables are ceilings on code written in that package, checked by the package a call is written in, with a compile-time check of the whole package. Packages without a table are unchanged. A package that calls another package is checked in its own file; what a package gets by calling a package with a wider ceiling is not tracked.
- `moxie fmt` (2026-11-03): indentation, blank lines, trailing spaces, final newline, operator and comma spacing, and blank lines before top-level declarations, with token, parse-tree, and idempotence checks before writing; long lines are broken at 80 columns (2026-11-04).
- Bin building and coverage (2026-11-03): `Bin(value: kind, ...)` as an expression builds an `Array[Byte]` (a value out of range aborts); a `when` of only `Bin` arms is checked by byte length, and arms with a literal, a guard, or a field-sized `bytes(n)` earn no credit.
- Language gaps (2026-11-03): (1) a call whose arguments are all constants and that fails a precondition is a compile error (the constants may be numbers, text, and booleans, with arithmetic, comparisons, `and`, `or`, `not`); (2) `curry(f)` is rejected at compile time when `f` has fewer than two parameters or a `ref`, `lazy`, `using`, or variadic parameter, `curryN` when `f` does not have N, `uncurry[n]` when n is not a constant of 2 or more or `g` has other than one parameter, and a call of `curry(f)(...)` or `uncurry[n](g)(...)` with the wrong number of arguments; (3) binary patterns `Bin(...)` are implemented for matching (section 8).
- The closing rule (2026-11-03, section 19): a closable resource that is bound to a name and released in the same scope counts once in a loop or recursion; a kept resource, and any atom, channel, timer, or future, created in a loop or recursion is a compile error because the pool cannot be sized. moxie/gc has no pools, so the rule does not apply there.
- Fiber limits and the pool header (2026-11-03, sections 13 and 19): `fiber[n] fn` is parsed, the entry package's `[fibers] limit` (validated, with `[pools]`) is the default, and `go` waits (and `try_go` returns NO_SLOT) when all of a function's slots are alive. The tally multiplies what a fiber function creates by its limit, counts the fibers it starts from their own limits, and reports the largest possible fiber count (the entry fiber plus every limit). A fiber function with no limit anywhere has an unknown multiplier: its resources print with a plus sign and a warning. `moxie pools FILE --header OUT` writes the pool header as JSON (counts per kind, null where unknown; fibers per function; the largest fiber count), which a runtime reads at startup.
- Splitting a fiber's memory (2026-11-04, section 3a): `[fibers]` takes `strings` (S-space) and `temps` (T-space) as a division of `memory`; the budget message shows the split; the interpreter does not enforce either space.
- Property tests (2026-11-04, section 22): `forall name Type, ...` inside `test` runs its body for 100 generated cases from a fixed seed (`moxie test --cases N --seed N`), shrinks a failing input, and reports the case, the seed, and the smaller input. Generators exist for the number types, `Bool`, `Char`, `String`, `List`, `Array`, tuples, declared tuples, and enums; the body must be pure; a type implements `Generatable` (`static fn generate(g Gen) Self`, optional `fn shrink`) to control how its values are made, with `gen_int`, `gen_bool`, `gen_pick`, and `sample[T]` to build them.
- The system (2026-11-04, section 19e): `now` and `monotonic` (a `Duration`, with `nanos`, `millis`, `seconds` to convert out), `random`, `random_int`, `random_bytes`, `seeded`, `exit`, `signals` (a channel of `#interrupt`, `#terminate`, `#hangup`), `cwd`, `home_dir`, `temp_dir`, `hostname`, `os_name`, `is_terminal`, `terminal_size`, `lookup_host`, `make_temp_file`, and `make_temp_dir`. Effect inference gains a third effect, uses the system. File watching is not designed.
- Platforms (2026-11-04, section 19e): `moxie --platform=browser` (and Try moxie) grants no network or ffi and refuses `signals` at check time; `os_name()` is `"browser"` there. Other platforms are not designed.
- Running other programs (2026-11-04, section 19e): `run_command` (to the end, with `stdin:`, `env:`, `cwd:`, `timeout:`) and `spawn` with `child_stdin`, `child_stdout`, `wait_child`, `kill_child`, behind a new permission kind `process` (`--allow-run`). There is no shell. Pseudo-terminals, process groups, and signals to a child other than kill are not designed.
- Dates and times (2026-11-04, section 19e): `DateTime` (no zone, defaults for the time fields), `to_utc`, `to_local`, `to_zone`, `to_instant`, `iso`, `format_time`, `parse_time`, `parse_iso`, `weekday`, `day_of_year`, and `days_in_month`. A `DateTime` has no zone and no arithmetic of its own; durations of days are 24 hours. Calendars other than the Gregorian, leap seconds, and time zone offsets in `parse_iso` are not designed.
- Unix sockets and named pipes (2026-11-05, section 19c): `listen_unix(path)` and `connect_unix(path)` reuse `Listener` and `Io`; `make_fifo(path)` and `open_file` on it give a named pipe. They need `fs.write` on the path. No anonymous in-process pipe: channels are for fibers and pipes are for processes, a pipe between two fibers could hang the whole program when full, and a spawned program's pipes already exist (`child_stdin`, `child_stdout`).
- Watching files (2026-11-05, section 19c): `watch(path)` returns a channel of `FileChange(path, kind)` with `#created`, `#modified`, `#deleted`. A polling thread (every 100 ms) keeps it portable and needs no library; the cost is that changes arrive in batches and two writes inside one tick may report once. One level deep for a directory. Needs `fs.read`. Reasoning: a build loop or a reload-on-save tool is the usual need, and a channel is how moxie already hands outside events to fibers (`signals`).
- Raw terminal input (2026-11-04, section 19e): `raw_terminal()` returns `Result[Terminal, Error]` (`MISSING` when standard input is not a terminal or the platform is the browser), `read_key(t)` returns `Result[Key, Error]`, and `Key` is a prelude enum (`Typed`, `Ctrl`, `Alt`, `Fn`, the named keys, `Other`). Raw means no echo, no line editing, and Ctrl-C and Ctrl-Z as keys; output processing is left alone. The terminal is restored by `close`, by exit, and by an abort; one `Terminal` at a time; needs `stdin`. Reasoning: a program that wants single keys (a menu, a game, a pager) should not need a library or a shell `stty`, and giving up the signal keys is the point of raw mode, so `signals()` is the way to still hear a kill.
- Static pool tally, first version (2026-11-03, section 19): `moxie pools FILE` counts the creation sites of each counted resource (Atom, Chan, Timer, Future, Connection, files, sockets, listeners, foreign handles) through the call graph. A count is exact (a true upper bound) when no site is in a loop, a comprehension, a daemon, or a recursive function and none is reached from `go`; otherwise it is printed as `N+` with the reason, because the number of runs of a site is not known statically, and `moxie --pools run` supplies the evidence. `--pools run` prints both reports and warns if an observed peak exceeds an exact count. The refusal of unbounded creation is the closing rule (a later entry); fibers and the header are the fiber multiplier entry.
- Permissions (2026-11-03, section 19d): kinds `fs.read`, `fs.write`, `net.connect`, `net.listen`, `ffi`, `stdin`, `env`, granted in `Moxie.toml` `[permissions]` or by `--allow-*` / `--deny-all` flags (flags replace the manifest). A program with neither is unrestricted; a `[permissions]` table restricts it. A denied call returns `Err(DENIED)`; an ungranted native library stops the program before it runs. The compiler follows the kinds through calls like effects and reports a kind that nothing grants. Paths are checked after resolving `..` and symbolic links. Per-package ceilings are in the Packages bullet of section 19d.
- Arrays of numbers and `Ptr[T]` (2026-11-03, section 19a): `Array[T]` of any number type crosses the boundary like `Array[Byte]` (copied in, `ref` copied back, `n UInt = len(a)` for the length), `size UInt = size_of(a)` gives the element size, and in a callback type `Array[T]` plus a length is one array while `Ptr[T]` is a `const T *` received as the value. `qsort` can be declared. `moxie bindgen` maps a number pointer followed by a length to an array.
- Handler callbacks (2026-11-03, section 19a): `cb Handler[F]` is a callback that C keeps and that must answer. On the scheduler's thread it runs at once; on a foreign thread it runs in a fiber of its own, which may park, while the C thread waits. A foreign function that waits for such a thread must be `parks`. `keeps` in `bindgen.toml` gives a `Handler` when the callback returns a value.
- Effect inference follows a call-site rule for function parameters (section 14).
- `trace(msg)` is added: a debug message to the error stream, exempt from effects and removed in release builds.
- A function may declare its effects (`pure`, `prints`, `parks`, `impure`); a declaration must agree with the inferred effects both ways, and on a bodyless interface member or forward declaration it is an upper bound for the impls (section 14).

## Decisions recorded on 2026-11-05

- `Secret[T]` wraps a value so that showing or printing it gives `Secret(***)`; `secret`, `reveal`, and `secret_eq` are the way in and out, and comparing with `==` is an error.
- `graphemes(s)` streams the user-perceived characters of a string, and `grapheme_count(s)` counts them; `len` still counts bytes.
- A Dict key larger than 64 bytes draws a warning; `key_warning` under `[program]` in `Moxie.toml` changes the limit.
- A type function (section 9a) that needs more than 64 reductions in one use is an error; `type_fuel` under `[program]` in `Moxie.toml` changes the limit (a whole number, 1 or more).
- Memoization is a documented recipe, not a prelude function.
- `Locale` carries separators, date order, 24-hour choice, and day and month names; `format_time` and `parse_time` read the one in scope or one passed as a third argument; `%x` and `%X` write the locale's date and time.
- The checker covers generics in part: operator bounds in the body, one type per parameter in a call, and type-argument counts.
- `go` moves its resource arguments; a second fiber needs `clone`.
- `moxie doc` turns `[`name`]` into a link to the item, within a page and across the pages of one run.
- Type lambdas `[A] -> T` (2026-11-05, section 9a): anonymous or named by a generic alias, first or higher order, applied by substitution, with no recursion and no type-level matching. Full type-level programming (type-level matching and recursion) was investigated and is not built; `TYPE-LEVEL.md` in the repository gives the analysis and the recommendation.

## Decisions recorded on 2026-11-26 (draft)

*Implemented on fp-primer: the expanded form, the `;` rule, and the removal of `!`. Everything under "Proposed" is not built or in the spec yet.*

- **Expanded form.** Inside `( ... )`, one item per line with no commas is allowed for parameters, arguments, constructors, and local-name lists. A line break ends an item when the item is complete and the next line starts a new one. A line starting with an operator, a keyword, a `.` method name, or `-` followed by a space continues the line above. A line starting with `-` directly followed by its operand starts a new item (`-b`). The open-tuple marker `...` starts a new item. The compact form (commas) is unchanged, and the two may mix in one call. Brackets `[ ]` and braces `{ }` have no expanded form.
- **Formatting.** `moxie fmt` keeps the form each call was written in and never converts one to the other. In an expanded call, a continuation line is indented two spaces inside the line that opens the call, and a closing `)` lines up with that line. A mixed call stays mixed.
- **Statements.** `;` may join statements anywhere inside a block. A one-line `then`, `do`, or `else` body, lambda, or arm takes one statement, so a `;` after it is an error.
- **Negation.** `!` is not a token. `not` is the only negation.

**Proposed: formatting.** Interpolation keeps one mechanism, `${expr}`. Formatting is a pipe of named steps, with no spec language inside the string:

    "${price |> fixed(2) |> pad_left(8)} | ${name |> pad_right(5)}"

The helpers are ordinary typed prelude functions. The existing `${expr:spec}` and `fmt` forms stay valid, so both styles work side by side. Whether the old forms are marked deprecated is open.

**Proposed: grouping.** `Locale` gets a group-size field: `(3)` for thousands, and `(3, 2)` for Indian grouping, where the last size repeats. `1234567` formats as `1,234,567` under `Locale.en_us` and `12,34,567` under `Locale.en_in`.

**Proposed: currency.** A currency is named in source by its ISO 4217 code, as in `|> money("USD")` and `|> money("INR")`. The code is the only identifier. `Locale` holds a table from code to display symbol: `$` for `USD` under `Locale.en_us`, and `₹` for `INR` under `Locale.en_in`. Where a symbol would be ambiguous, the locale shows a prefixed form such as `CA$`, or the code itself. Symbols are display only and never identify a currency.

**Decided (2026-11-26).**

- **`money` is a type with arithmetic.** A `Money` value holds an exact `Decimal` amount and its ISO code. `+` and `-` work only between two values with the same code, and a mix is a compile error when both codes are literals and an `Err` otherwise. `*` and `/` take a `Decimal` or `Int` factor. Comparisons follow the same rule as `+`. Arithmetic is exact; nothing rounds until display or an explicit `round_to`.
- **Rounding.** Display rounds to the currency's minor units (2 for `USD`, `INR`, and `EUR`; 0 for `JPY`). A stored value is rounded only when the program asks.
- **Helper names.** `fixed(x, places)`, `pad_left(s, width)`, `pad_right(s, width)`, `percent(x, places)`, `money(code)`. They use the spec's existing verbs and take no spec strings.
- **`fmt` templates and `${expr:spec}`.** Not deprecated, and both stay valid. The pipe form is an addition; it is not the preferred form for simple values, which stay in the existing syntax.
- **Placement.** Each `Locale` records whether the symbol goes before the amount and whether a space separates them. `Locale.en_us` puts `$` before with no space, `Locale.de_de` puts `€` after with a space (`1.234,50 €`), and so on.
