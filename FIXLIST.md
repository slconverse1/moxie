Colonless syntax (Steve, 2026-11-12; now `main`, the old syntax is on `oldmain`)
* A block no longer starts with a colon: the indented lines below a header are the block. One-line forms: `if c then a elif c then b else d`, `for x in xs do body`, `while c do body`, `fn f(x) Int = body`, lambdas `(x) -> body`, accessors `get -> e`, `x.do -> e`. `else` in `when`/`select`/`seq` takes no arrow. A one-line `if` may not be mixed with block branches. The old form is an error that says to delete the colon.
* Colons that stay: annotations, `Dict("a" -> 1)` keys, named arguments, labels, `update field: value`, format specs.
* Declarations lose their colon too (Steve, 2026-11-12): `fn f(x Int, y String)`, tuple fields `name String`, enum cases `Circle(r Float)`, bounds `[T Ord]`, tuple and function types `(x Int) -> Int`, `forall xs List[Int]`, `ref n Int`. Values keep the colon: `User(name: "Al")`, `(x: 1, y: 2)`, `update` lines. A binding is a declaration too, so its type follows the name: `total Int = 0` (Steve, same day; the REPL echo, `$res1 Int = 25`, matches). The old declaration colon is an error that says to delete it.
* The positional 1-tuple is `(:40)` (shorthand for `(0: 40)`; it was `(%40)` for a few hours, changed by Steve the same night), and `show` prints it that way. A `Dict` entry is `key -> value` (literals, comprehensions, patterns, `show`, and `read`). A bare name is a pun: `Dict(age, n)` is `Dict(age -> age, n -> n)`, and after a named argument `User(name: who, age)` is `age: age`. `tools/declcolon.py` converts old source (the parser decides which colons are declaration colons); `tests/run_decls.py` covers it.

Open design ideas (Steve, 2026-11-13; nothing built)
* Type delegation, Kotlin's class delegation (`class Logger(p: Printer) : Printer by p`): a type hands a whole interface to a value it holds, and the compiler writes the forwarding methods, so the mixer writes only the methods that differ. Name: `proxy`, a soft keyword in an `impl` header, beside `delegate` (a field takes its reads and writes from a helper type, Kotlin's property delegate), so the two words never touch. Sketch: `impl Printer for Logger proxy(printer)`, then only `print_message` is written and `print_status` forwards to the `printer` field. Today the forwarders are written by hand. Open: two proxied interfaces with the same method name, whether a `ref` method can forward, and what happens if the held value does not implement the whole interface. `delegate` stays as it is: renaming it would touch the parser, both Specs, both Guides, the intros and the tests. Names considered and set aside: `field_delegate`/`type_delegate` (each would name the opposite of its argument: a field delegate takes a type, a type delegate takes a value), `val_delegate`, `forward_to`.

* Safety levels chosen by the mixer (Steve, 2026-11-13; nothing built). Two declared markers on the function that introduces the risk, using the effect machinery (inferred through callees, declared before `fn`, checked both ways, shown in the summary file; a missing marker is a compile error, as for a foreign function): `unsafe fn` for operations that can break type or memory guarantees (raw `Ptr[T]` handling and pointer casts in foreign calls, today covered only by the package-wide `ffi` permission), and `dynamic fn` for operations on `Dyn` that are checked at run time (abort or `Err`). Operations that merely abort (`a(i)`, overflow, division by zero) stay as they are: the Spec says dropping provably redundant checks needs no `unsafe`. Callers inherit a marker and it is reported; a `Moxie.toml` setting such as `safety = "strict"` could make an untagged caller an error. Open: whether a lambda may use `Dyn` (it does not affect purity, so probably yes, reported).
* `Dyn`, a closed data type (Steve, 2026-11-13; nothing built): an enum of null, bool, number, string, list and string-keyed map, so reading `d("name")` is an ordinary lookup and needs no run-time reflection. Conversions to and from the mixer's own types are generated at compile time, like `deriving show` and `deriving read` (`deriving dyn`, with a checked `from_dyn` giving a `Result`); a type that does not derive it, a function and a closure cannot be converted. It covers data from outside (JSON, config, HTTP bodies), not calling a method unknown at compile time (`any Interface` already gives run-time dispatch). It needs boxed values, which sits badly with the no-GC memory budgets, so it may belong in moxie/gc first. The Spec lists reflection and run-time code as left out on purpose: this keeps that rule (no reflection) while giving data dynamism.
* Frictions found while writing examples (2026-11-13), in order of cost: (1) a pattern that can never match, such as `Some(n)` against a `Result` from `first(xs)`, compiles and silently takes the `else` path: it should be a type error; (2) `0 <= x <= 100` fails with "cannot compare `Bool` and `Int`": support chaining or say "use `and`"; (3) let-else cannot see the failure it leaves on, so the `Err` cannot be logged or its code used; (4) a function body cannot end with a bare `a, b` although `lo, hi = f()` binds without parentheses; (5) a pair needs a `tuple` header, a block and one line per field: a one-line `tuple Point(x Int, y Int)` would match enum cases; (6) lookups disagree: `xs(0)` aborts, `get` and `first` return `Result`.
* `Dyn` first slice built (2026-11-13): `moxie/std/json.mxi`, `import json`, `tests/run_json.py`. Done: enum, lookups, `as_*`, `parse`, `to_json`. Left: `deriving dyn` and `from_dyn`, the `dynamic fn` marker, `\u` escapes, pretty printing, a path lookup helper, a `Dict`-free map type that is quick to look up in a large document.
